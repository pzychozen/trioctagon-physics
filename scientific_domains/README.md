New navigation metadata, 30 September 2026. This index describes the accepted
ownership model at the frozen pre-separation baseline `v0.1.0`, commit
`c8edbc46bc9b8e122b59b2039460a2eec5202475`. It adds no mathematical authority,
runtime contract, publication edition or permission to move existing artifacts.

**CURRENT SCIENTIFIC KERNEL != HISTORICAL TORMENT KERNEL**

| Scientific surface | Start here | Authority boundary |
|---|---|---|
| Scientific Core / Core Geometry | [Current kernel, papers and Atlas](CORE_GEOMETRY.md) | Accepted mathematics within its recorded scope; public support is narrower than package membership. |
| TORMENT / Historical | [Reconstruction and preservation](TORMENT_HISTORICAL.md) | Frozen old mathematics, source evidence and qualified reconstruction; admission to current science requires separate review. |
| Research Lab / Experimental | [Investigations and open interfaces](RESEARCH_LAB.md) | Intentional experiments, conditional models and finite-history studies; no automatic promotion to accepted science. |

These are scientific responsibilities, not new storage roots or copyright
assignments. A directory can contain mixed statuses. Shared ancestry, equations,
terminology or implementation history does not make the three surfaces one
current model. UI exposure does not grant scientific authority.

## Reading authority

For current science, follow the accepted paper editions and their scoped
acceptance, the owning current implementation, contracts and verification
records linked from [Core Geometry](CORE_GEOMETRY.md). Later explicit dispositions
resolve dated pending wording; they do not rewrite the original receipts.
The Atlas explains derivations and boundaries without silently revising papers.

Historical reconstruction supplies evidence and possible future analysis
objects. A separately reviewed admission must identify the selected mathematics,
variant, input domain, provenance and support contract. Experimental work needs
its own scientific review before becoming current accepted mathematics.
New navigation cannot supply either admission.

## Scientific-status vocabulary

These labels describe individual claims or artifacts in this navigation layer.
They do not replace the literal statuses in frozen records. More than one can
apply to a bundle; mathematical acceptance and software support are separate.

| Status | Plain-language meaning |
|---|---|
| `CURRENT_ACCEPTED_MATH` | Mathematics accepted for the current project within explicit assumptions and limits; not necessarily a public API. |
| `HISTORICAL_RECONSTRUCTED_MATH` | Mathematics recovered from historical sources, with its original variants and reconstruction qualifications. |
| `EXPERIMENTAL_ENGINE` | A research implementation of a proposed model; execution or availability does not certify its mathematics. |
| `EMPIRICAL_FINITE_HISTORY` | Observations from a specified finite dataset, trajectory or horizon; not a general theorem or causal law. |
| `MODEL_CHOICE` | An adopted convention, parameter, normalization or modeling assumption; not a derived physical law. |
| `OPEN_PHYSICAL_INTERFACE` | A physical interpretation, calibration, coupling or attachment that remains unresolved. |
| `PUBLICATION_EVIDENCE` | Papers, proofs, reviews, snapshots, fixtures and recorded results; their roles and claims must be read individually. |
| `INFRASTRUCTURE` | Navigation, packaging, schemas, contracts and preservation machinery; no new scientific claim by itself. |
| `UNKNOWN_REQUIRES_REVIEW` | Ownership or claim status is unresolved; do not infer acceptance from location or naming. |

## Future application features

Derive supported current operations from `kernel_physics.api` and its documented
contracts. An accepted internal theorem needs a separate support decision before
becoming an application API. A historical candidate needs a reviewed modern
analysis contract; research engines need explicit authorization and visible
experimental status. Preserve source, variant, dataset and result provenance.
Neither a plot nor an application control changes those rules.

The [existing application](../apps/scientific_ui/README.md) has a separately
[locked kernel artifact](../apps/scientific_ui/kernel-artifact.lock.json), sourced
from `7b3a0fcec2c9bde6c9e1ea482fe1f1ea6b16793e`. That identity differs from the
repository baseline above. Navigation does not update or recertify that pairing.
Application architecture mapping is a later task.
