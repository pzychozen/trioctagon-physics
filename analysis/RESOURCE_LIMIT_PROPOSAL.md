# B1 measured deployment-limit proposal — NOT APPROVED

This document proposes review values, not defaults or approved production limits.
B1 has no verified result lane. Do not activate these numbers merely by importing
the package or copying this document into an approval record.

## Evidence and method

Before B1, the preserved repository census contained 2,973 tracked/untracked files.
Static inspection of its 519 JSON files found no standalone top-level
`KERNEL_RUN_RECORD` object. Existing supported fixture generators were inspected,
especially `kernel_physics/tests/test_runner_records.py:14–31`: default two
updates, optional observers/readouts/diagnostics; fixtures are generated by tests,
not stored record files. They were not run for this measurement.

A handcrafted B1 fixture was accepted by the unchanged public RunRecord loader.
It deliberately identifies itself as TEST_ONLY and contains supplied values
rather than a simulated trajectory. Its two samples start at update index 7.
It has raw chirality and all 15 accounting fields, including signed zeros and
oppositely signed residuals. SHA-256:
`5dcf1a30945d290a4a1109c73439a390f56397eb9e7765c424d379eca59ea0a7`.

For measurement only, this structural fixture was expanded by copying sample
objects and assigning contiguous indices; the native digest was reconstructed
from the documented test-fixture projection. No recurrence, observer, diagnostic,
norm or other scientific operation was called. ParentSnapshot used the supported
public loader, and the provider copied the last selected sample's 16 fields.

Measurements used Command Prompt / conda torment, Python 3.11.15, Windows x64,
NumPy 2.4.4, SymPy 1.14.0 and mpmath 1.3.0. The first load includes import costs;
subsequent rows are warm. Timings include tracemalloc overhead. Tracemalloc
measures Python allocations and may omit native-library/OS memory; these figures
are not process-RSS or worst-case memory guarantees.

## Proposed values for review

| Limit | Proposal | Measurement-based margin |
|---|---:|---|
| Input bytes | 64 MiB = 67,108,864 | Next power of two above four times the largest measured parent. |
| Samples | 40,000 | Four times the largest measured structural sample count. |
| JSON depth | 16 containers | Next power of two above twice the observed depth 7. |
| Complete artifact output | 128 KiB = 131,072 | Next power of two above four times the synthetic full artifact, not just the small selected payload. |
| Wall time | 210,000 ms | Round eight times the largest traced load+copy time up to a 30-second interval. Includes workload expansion and variation margin; not a latency promise. |
| Memory | 4 GiB = 4,294,967,296 | Next power of two above eight times the largest traced peak; native/RSS and protected-snapshot costs remain to be measured in B2. |
| Primary diagnostic | 1,024 Unicode characters | Next power of two above eight times the measured 87-character refusal. B2 must separately bound total retained log/evidence bytes. |

Logical scope is fixed independently: one parent, one ordinal, 1–16 distinct
ordered fields, at most 20 numeric leaves, zero external data, one active attempt
per process lane. Provider output does not grow with history length; public parent
validation currently parses the whole record, so history length still dominates
time/memory.

## Review conditions and known limits

These samples cover the first APP04 extraction shape, not every valid Core record
with many observers, other diagnostics or large provenance strings. The existing
Core loader has no new B1 sample/byte/time/memory maximum; its validation domain
must not be narrowed silently. UI sample/large-file warnings are not production
resource approval.

No known saved Core record was excluded by an enabled B1 policy: none is enabled.
The schema-supported domain can exceed any finite operational envelope. A later
approved refusal must be labeled resource-policy refusal, never “invalid Core
science.” Review real retained records and richer supported fixture shapes before
deployment; if a proposed limit excludes known required records, revise it
explicitly or add a separately reviewed bounded access design.

B1 enforces explicit caller byte/depth/sample/payload/diagnostic budgets for its
bounded inspection routines and limits concurrency. It only models wall-time/
memory policy; it does not claim OS enforcement. B2 must measure its actual
protected installation, native/RSS peak, cold/warm runs, full attestation record
size, failure diagnostics and interruption/cleanup behavior. It must then obtain
finite-policy approval and enforce time/memory/effect boundaries before issuing
verified artifacts.
