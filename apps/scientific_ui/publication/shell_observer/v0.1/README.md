# Spherical Edge Observer — accepted source publication

This edition publishes the accepted SHELL-APP P1R1 native observation panel and its unchanged required export-access repair. In the scientific application, open **C — Geometry → Spherical Edge Observer**. The existing C01 / D03 record workspace remains separate. See the [application guide](../../../README.md), [publication disposition](PUBLICATION_DISPOSITION.md), [retained validation summary](RETAINED_VALIDATION.md) and [exact source manifest](PUBLICATION_MANIFEST.json).

Original, Crossing A and Crossing B select the accepted exact events. A has whole chord C/w = 1; B has added extension ell/w = 1 at each endpoint. The panel retains all 42 edge-branch identities. Exact-event incidence networks and their convex hulls are separate optional layers. Generic observations preserve branch identities without inferring coincidences, event topology or a certified distinct-position count. Assigned radius comparisons are comparison scales, not physical boundaries.

Custom normalized radius R, chord C or extension ell requires explicit Apply. Exact decimal length identities and named exact presets retain their provenance; radius proximity does not establish an event. Width is a positive similarity scale, not an implicit metre. Presentation units may use width, original edge, chord or nonzero extension; centered and Paper C global frames are distinct. Pending or invalid input keeps the displayed observation marked STALE and disables exports. P1R1 closes F01 (pending-width/input-mode provenance) and F02 (persistent validity and clipping status).

JSON observations and PNG/SVG images with sidecars retain input, adjustments, frame/units, view/clipping and actual module/resource identities. Images are numerical presentations. Image and sidecar publication uses two no-replace operations, not an atomic pair; consumers must validate matching hashes. There is no shell importer or CSV export.

The scientific authority is the [accepted Spherical Edge Extensions edition](https://github.com/pzychozen/trioctagon-physics/tree/0997e565f2ddbd350d3c50e5d3af26c651d8b4c9/papers/SPHERICAL_EDGE_EXTENSIONS) and its [research evidence](https://github.com/pzychozen/trioctagon-physics/tree/0997e565f2ddbd350d3c50e5d3af26c651d8b4c9/research/spherical_edge_extensions). The packaged reference is an immutable byte copy of its accepted viewer data, with eight canonical source mappings. The native implementation uses no archived HTML/Plotly viewer or research checker at runtime. Earlier statements that application integration was absent describe the original research checkpoint; those sources and their HTML are unchanged.

This is observation software, not a kernel model, physical wall or energy law. Numerical bounds, V01 endpoint policy, export qualifications and UI limitations remain as accepted. No application installation, package release or deployment accompanies this source publication.
